# RV / VISION

RV1126B 多摄像头 WebRTC 本地监看台。接收板端 8 个摄像头位置的主、子码流，并在浏览器中自动显示当前存在的摄像头。

## v12 / v2.0.1 修复内容

- 修复开机时“检测到信号”被误显示为“画面正常”：连接阶段显示“已检测到，正在连接”，实际收到并解码视频后才显示绿色状态。
- 增加单路 WebRTC 无画面恢复：连续 12 秒没有解码帧增长时，自动重建该路连接，不重启其他摄像头或 AP 热点。
- 开机预热不再读取历史日志判断视频就绪；改为确认当前已检测到通道的主、子码流帧计数持续增长，最多等待 20 秒。
- 修复设备接口失联后仍保留正常状态、选中离线通道仍显示绿点，以及旧播放器异步回调影响新连接的问题。
- 保留 v11 的 AP 启动修复、人员识别、录像配置和主/子码流切换。

已验证两路实际视频播放、无首帧自动恢复、单路离线状态和接口断开后的恢复。尚未重新进行冷启动验证；本版本不替换摄像头或 Wi-Fi 驱动，也不包含重新编译的板端二进制。详细说明见 [v2.0.1 发布说明](RELEASE_NOTES_v2.0.1.md)。

## v11 / v2.0.0 新增功能

- 同步板端 AP 启动修复：AP 模式启动前清理占用 `wlan0` 的残留 `wpa_supplicant`，减少 STA/AP 抢占导致热点不发 Beacon 的情况。
- 增加 AP 配置校正和多次状态确认：针对 `rkwifi_server` 异步写入的配置，启动前统一为 WPA2-PSK/CCMP，并保留 `192.168.0.1` 管理地址。
- 修复重启后视频服务可能因缺少 `/oem/usr/lib` 而找不到 Rockchip 运行库的问题，补齐视频进程的 `LD_LIBRARY_PATH`。
- 保留 v10 的 RKNN 人员识别检测框、摄像头聚焦查看、轨迹保持和录像/RTC 功能。

说明：本版本修复的是 AP 启动竞态、配置兼容性和运行库加载路径；如果 AIC8800 的内核模块或固件本身异常，仍需更换匹配的厂商驱动/固件，不能仅靠启动脚本解决。

## v9 / v1.2.0 新增功能

本版本以 RV1126B 板端当前运行文件为准，网页入口和 MediaMTX 配置与 v8 保持一致，并同步最新的板端启动脚本。

- 修复板端掉电或 RTC 时间异常后录像文件日期可能错乱的问题：启动时优先读取硬件 RTC，并保留有效的较新内核时间。
- 新增 `/userdata/rv1126b-clock.state` 时钟状态持久化，在 RTC 不可靠时恢复最近一次有效时间。
- 允许使用最近已封存 MP4 文件名恢复时间，同时拒绝明显的未来时间戳，避免录像被列到错误日期。
- 固定板端启动脚本使用 `Asia/Shanghai` 等效时区配置，使录像文件名、日志和日期筛选保持一致。
- 保留已有的 AP、以太网、RTSP、MediaMTX、网页服务和录像启动顺序；不改写板端 `/videotuiliu/record.cfg`。

当前板端已验证的录像配置为：主码流、30 秒分片、2048 MB 预留空间、80% 最大使用率。该运行时配置不写入仓库，避免把设备状态误当成通用默认值。

本次发布不包含板端已编译的 `ap_board_web_server`、`mediamtx` 和 `videotuiliu` 二进制；仓库保存网页快照、启动脚本、配置模板和桌面端程序源码。

## v6 新增功能

本分支以 RV1126B 板端当前运行版本为基础，包含已上传到板端 `/userdata/rv_web/` 的网页资源和对应的本地 WebRTC 服务改动。

- 新增连续录像播放接口 `GET /api/recording/stream`，按摄像头和起始分片读取已封存 MP4，并通过 FFmpeg 无转码拼接输出连续视频。
- 连续播放严格限制摄像头白名单、合法 MP4 文件名和已封存文件，不读取正在写入的 `.mp4.part`，避免路径穿越和半文件播放。
- 录像管理改为完整历史时间轴，支持拖动定位、分片自动衔接、单路摄像头播放和后台加载更早录像。
- 录像列表增加按日期筛选和一键清除筛选，筛选结果同时作用于列表和连续播放时间轴。
- SD 卡录像管理弹窗重新美化：统一筛选控件、播放器容器、时间轴、列表表头以及播放/下载/删除操作按钮，并适配移动端窄屏。
- 板端静态资源同步更新，页面实际引用的 `styles-wifi.css` 与主样式保持一致，避免板端继续加载旧版界面。

## v5 新增功能（历史版本）

`board_v5/` 最初从 RV1126B（`192.168.100.125`）运行版本取回，后续版本继续在该目录维护。v8 页面实际入口为 `app-network-memory-v5-filter.js`。

- 单个摄像头显示一条完整历史时间轴，不再把 30 秒录像误解为互相独立的播放任务。
- 时间轴只纳入已经封存完成的 `.mp4`，正在录制的 `.mp4.part` 不参与时间轴，避免拖动到尚未完成的文件。
- 播放时按时间顺序自动切换 30 秒分片；当前分片结束后自动进入下一段，用户看到的是连续录像。
- 时间轴支持直接拖动到历史位置，系统会计算目标分片和分片内偏移后切换播放。
- 每段录像读取真实时长后重新校准总时间轴，避免最后一段不足 30 秒时产生明显偏差。
- 打开录像管理后先显示最近分片，再在后台按页读取更早录像；关闭窗口会取消后续加载，减少 SD 卡目录很大时的卡顿。
- 下层 CH1 和上层 CH1 的子码流启动预热，系统启动时先确认这两路 RTSP 已上线，再开放网页服务，减少“网页已打开但视频还在等待”的情况。
- 网络指示灯在页面启动后自动读取 Wi-Fi/AP 状态，并每 5 秒刷新；有线接口的 `/api/streams` 可达、Wi-Fi 已连接或 AP 已开启时都会显示绿色，不需要点击网络按钮触发刷新。
- 录像管理增加按日期筛选和一键清除筛选，筛选结果同时作用于录像列表和连续播放时间轴，减少 30 秒分片过多造成的混乱。

## v3 新增功能

## 特点

- Rust 负责页面、状态和热插拔管理，MediaMTX 负责 RTSP 到 WebRTC/WHEP 协议转发。
- H.264 全程直通，不解码、不重新编码，也不再产生 HLS 分片。
- 默认同时管理 16 个流：上下两层板 × CH1–CH4 × 主/子码流。
- 摄像头拔掉后显示离线，重新插入后自动恢复，不需要刷新网页。
- 通过板端只读状态接口 `http://192.168.100.125:8555/state.json` 获取真实热插拔状态，只连接实际存在的摄像头。
- 视频墙默认使用子码流，并严格保持每路摄像头当前选择的主、子码流。
- 左侧“设置”集中管理网络、主/子码流和 SD 卡录像参数，并从板端读取当前真实配置。
- 存储与录像设置可启停录像、选择主/子码流、设置分片时长和空间保护阈值；只录制当前在线的摄像头。
- RV1126B 使用硬件 H.264 编码，浏览器 WebRTC 优先使用平台硬件解码。

## 启动

双击 `start-video-wall.cmd`，程序会自动启动并打开：

```text
http://127.0.0.1:9076
```

首次启动会自动下载官方 MediaMTX v1.21.0，并验证 SHA-256。需要预先安装 Rust GNU/LLVM 工具链：

```powershell
rustup toolchain install stable-x86_64-pc-windows-gnullvm
```

停止服务：双击 `stop-video-wall.cmd`，或在 PowerShell 中运行：

```powershell
.\stop.ps1
```

## 板端地址映射

- 下层板 CH1–CH4：`/lower/ch1` 至 `/lower/ch4`
- 上层板 CH1–CH4：`/upper/ch1` 至 `/upper/ch4`
- 每个通道后缀：`/main` 或 `/sub`
- 网页会严格保持每路手动选择的主/子码流。
- MediaMTX 对 H.264 只做协议转发，不在电脑端软件重编码；浏览器负责解码。

例如：

```text
rtsp://192.168.100.125:8554/lower/ch1/main
rtsp://192.168.100.125:8554/lower/ch1/sub
```

## 编码配置接口

电脑端公开 `GET/POST /api/config`，并代理板端 `8555` 端口的 `GET/POST /config.json`。请求与响应格式一致：

```json
{
  "main": { "width": 1280, "height": 720, "fps": 25, "bitrate_kbps": 3072 },
  "sub": { "width": 640, "height": 360, "fps": 15, "bitrate_kbps": 512 }
}
```

配置是 8 路摄像头共用的主、子码流模板。板端不可达或拒绝配置时，网页会显示原始错误，不会将本地默认值显示为已生效。

## SD 卡录像

电脑端公开 `GET/POST /api/recording`，代理板端的 `/record.json`。网页“设置”中的“存储与录像”可以设置：

- 是否持续录像；
- 使用主码流或子码流；
- 分片时长（默认 30 秒）；
- 最少保留空间和最大磁盘使用率。

录像的分辨率、帧率和码率跟随所选主/子码流，可在“设置”的“显示码流”分类中调整。板端直接复用 RV1126B
硬件编码后的 H.264 数据写 MP4，不在电脑端录制或软件转码。每个在线摄像头单独写入：

```text
/mnt/sdcard/recordings/lower-ch1/
/mnt/sdcard/recordings/lower-ch2/
...
/mnt/sdcard/recordings/upper-ch4/
```

`/mnt/sdcard/recordings/all/` 是全部录像的统一索引，使用符号链接，不会重复占用 SD 卡空间。摄像头拔出后该路立即停止并封装当前文件，重新插入后自动继续。空间达到保护阈值时，板端会按时间删除最旧的已完成 MP4；正在写入的 `.mp4.part` 不会被删除。

请求示例：

```json
{
  "enabled": true,
  "source": "sub",
  "segment_seconds": 30,
  "reserve_mb": 2048,
  "max_usage_percent": 85
}
```

点击网页“SD 卡录像”区域的“管理”，可以按摄像头查看已封存的 MP4，并直接播放、下载或删除。列表只公开经过板端白名单校验的摄像头目录和 `.mp4` 文件名，不允许访问 SD 卡上的其他路径。
