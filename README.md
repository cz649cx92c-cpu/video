# RV / VISION

RV1126B 多摄像头 WebRTC 本地监看台。接收板端 8 个摄像头位置的主、子码流，并在浏览器中自动显示当前存在的摄像头。

## v5 新增功能（当前 RV1126B 板端版本）

本分支的 `board_v5/` 是从正在运行的 RV1126B（`192.168.100.125`）直接取回的发布快照，网页入口是 `app-network-memory.js`。

- 单个摄像头显示一条完整历史时间轴，不再把 30 秒录像误解为互相独立的播放任务。
- 时间轴只纳入已经封存完成的 `.mp4`，正在录制的 `.mp4.part` 不参与时间轴，避免拖动到尚未完成的文件。
- 播放时按时间顺序自动切换 30 秒分片；当前分片结束后自动进入下一段，用户看到的是连续录像。
- 时间轴支持直接拖动到历史位置，系统会计算目标分片和分片内偏移后切换播放。
- 每段录像读取真实时长后重新校准总时间轴，避免最后一段不足 30 秒时产生明显偏差。
- 打开录像管理后先显示最近分片，再在后台按页读取更早录像；关闭窗口会取消后续加载，减少 SD 卡目录很大时的卡顿。
- 下层 CH1 和上层 CH1 的子码流启动预热，系统启动时先确认这两路 RTSP 已上线，再开放网页服务，减少“网页已打开但视频还在等待”的情况。
- 网络指示灯在页面启动后自动读取 Wi-Fi/AP 状态，并每 5 秒刷新；有线接口的 `/api/streams` 可达、Wi-Fi 已连接或 AP 已开启时都会显示绿色，不需要点击网络按钮触发刷新。

板端快照文件与运行位置对应如下：

| 快照文件 | 板端位置 |
|---|---|
| `board_v5/app-network-memory.js` | `/userdata/rv_web/app-network-memory.js` |
| `board_v5/index.html` | `/userdata/rv_web/index.html` |
| `board_v5/styles.css` | `/userdata/rv_web/styles.css` |
| `board_v5/rv1126b_autostart.sh` | `/userdata/rv1126b_autostart.sh` |
| `board_v5/mediamtx-rv1126b.yml` | `/userdata/mediamtx-rv1126b.yml` |

## v4 新增功能

- 修复录像管理中的播放和下载兼容性：当板端录像列表没有返回完整文件 URL 时，网页会自动使用摄像头白名单和合法 MP4 文件名拼接 `/api/recording/file` 接口。
- 修复录像预览按钮在缺少 URL 字段时无法播放的问题，并继续保留网页播放、下载和删除能力。
- 简化 SD 卡录像设置界面，隐藏当前后端不实际使用的“保留空间”输入，只保留有效的最大使用率保护参数，避免用户配置出不会生效的值。

## v3 新增功能

- 新增 SD 卡持续录像，可选择主码流或子码流作为录像源。
- 默认按 30 秒封装一个 MP4；突然断电通常只影响正在写入的最后一个分片。
- 只录制当前已插入且信号正常的摄像头；拔出后停止该路，重新插入后自动恢复。
- 每个摄像头使用独立目录，并提供 `/mnt/sdcard/recordings/all/` 总索引；总索引使用符号链接，不重复占用容量。
- 新增空间保护：最大使用率默认 85%，并可设置最少保留空间；达到阈值后自动删除最旧的已封存录像。
- 新增录像管理窗口，可按全部或单个摄像头筛选，显示录像时间与大小，并支持网页播放、下载、删除和继续加载更早录像。
- 板端复用 RV1126B 硬件编码后的 H.264，不在电脑端软件转码；每个摄像头使用独立录像线程和有界队列。
- 新增电脑端 `GET /api/recordings`、`DELETE /api/recording/file` 接口，文件访问限定为八个摄像头目录中的合法 MP4 文件。

## 特点

- Rust 负责页面、状态和热插拔管理，MediaMTX 负责 RTSP 到 WebRTC/WHEP 协议转发。
- H.264 全程直通，不解码、不重新编码，也不再产生 HLS 分片。
- 默认同时管理 16 个流：上下两层板 × CH1–CH4 × 主/子码流。
- 摄像头拔掉后显示离线，重新插入后自动恢复，不需要刷新网页。
- 通过板端只读状态接口 `http://192.168.100.125:8555/state.json` 获取真实热插拔状态，只连接实际存在的摄像头。
- 视频墙默认使用子码流；聚焦时保持用户当前选择，不会自动切换主码流。
- 右侧主、子码流卡片的齿轮分别打开对应设置，并从板端读取后统一调整 8 路摄像头的分辨率、帧率和码率。
- 右侧“SD 卡录像”齿轮可启停录像、选择主/子码流、设置分片时长和空间保护阈值；只录制当前在线的摄像头。
- RV1126B 使用硬件 H.264 编码，浏览器 WebRTC 使用平台硬件解码优先；右侧显示实际统计或硬件能力检测结果。

## 启动

双击 `start-video-wall.cmd`，程序会自动启动并打开：

```text
http://127.0.0.1:9076
```

首次启动会自动下载官方 MediaMTX v1.21.0，并验证 SHA-256。需要预先安装 Rust GNU/LLVM 工具链：

```powershell
rustup toolchain install stable-x86_64-pc-windows-gnullvm
```

停止服务：双击 `stop-video-wall.cmd`，或在 PowerShell 中运行：

```powershell
.\stop.ps1
```

| 名称 | 默认值 | 说明 |
|---|---|---|
| `RV1126B_HOST` | `192.168.100.125` | 板子 IP |

## 板端地址映射

- 下层板 CH1–CH4：`/lower/ch1` 至 `/lower/ch4`
- 上层板 CH1–CH4：`/upper/ch1` 至 `/upper/ch4`
- 每个通道后缀：`/main` 或 `/sub`
- 网页会严格保持每路手动选择的主/子码流；进入聚焦模式不会自动切换。
- MediaMTX 对 H.264 只做协议转发，不在电脑端软件重编码；浏览器负责解码。

例如：

```text
rtsp://192.168.100.125:8554/lower/ch1/main
rtsp://192.168.100.125:8554/lower/ch1/sub
```

## 编码配置接口

电脑端公开 `GET/POST /api/config`，并代理板端 `8555` 端口的 `GET/POST /config.json`。请求与响应格式一致：

```json
{
  "main": { "width": 1280, "height": 720, "fps": 25, "bitrate_kbps": 3072 },
  "sub": { "width": 640, "height": 360, "fps": 15, "bitrate_kbps": 512 }
}
```

配置是 8 路摄像头共用的主、子码流模板。板端不可达或拒绝配置时，网页会显示原始错误，不会将本地默认值显示为已生效。

## SD 卡录像

电脑端公开 `GET/POST /api/recording`，代理板端的 `/record.json`。网页中的 SD 卡录像齿轮可以设置：

- 是否持续录像；
- 使用主码流或子码流；
- 分片时长（默认 30 秒）；
- 最少保留空间和最大磁盘使用率。

录像的分辨率、帧率和码率跟随所选主/子码流，可在对应码流卡片的齿轮中调整。板端直接复用 RV1126B
硬件编码后的 H.264 数据写 MP4，不在电脑端录制或软件转码。每个在线摄像头单独写入：

```text
/mnt/sdcard/recordings/lower-ch1/
/mnt/sdcard/recordings/lower-ch2/
...
/mnt/sdcard/recordings/upper-ch4/
```

`/mnt/sdcard/recordings/all/` 是全部录像的统一索引，使用符号链接，不会重复占用 SD 卡空间。摄像头拔出后该路立即停止并封装当前文件，重新插入后自动继续。空间达到保护阈值时，板端会按时间删除最旧的已完成 MP4；正在写入的 `.mp4.part` 不会被删除。

请求示例：

```json
{
  "enabled": true,
  "source": "sub",
  "segment_seconds": 30,
  "reserve_mb": 2048,
  "max_usage_percent": 85
}
```

点击网页“SD 卡录像”区域的“管理”，可以按摄像头查看已封存的 MP4，并直接播放、下载或删除。列表只公开经过板端白名单校验的摄像头目录和 `.mp4` 文件名，不允许访问 SD 卡上的其他路径。
